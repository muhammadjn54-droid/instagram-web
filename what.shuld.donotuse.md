# Что НЕ использовать (указатель)

> **Канонический файл — [`backend/what.shuld.donotuse.md`](file:///c:/Users/muham/Desktop/instagram-monorepo/backend/what.shuld.donotuse.md).**
> Все правила живут там. Этот файл оставлен только как указатель, чтобы в проекте
> не было двух противоречащих друг другу версий одного документа.
> Обновлено: 2026-10-21.

Кратко (полные правила и обоснования — в каноническом файле):

| # | Правило |
|---|---|
| 1 | Не использовать микросервисы, gRPC, CQRS, шины сообщений (Kafka/RabbitMQ) |
| 2 | Не делать 10 слоёв абстракций (Clean Architecture / DDD по книжкам) |
| 3 | Не использовать `any` и `@ts-ignore` |
| 4 | Не устанавливать лишние npm-пакеты |
| 5 | Не хранить пароли в открытом виде и секреты в коде |
| 6 | Не писать весь код в одном файле: один модуль = одна папка в `src/modules/` |
| 7 | Новые маршруты — REST style (plural, kebab-case, id в пути); legacy `/Account/*` не переименовывать |
| 8 | `swagger.old.json` — справочник фич, а не контракт URL |
| 9 | Не менять бизнес-логику, когда просят только документацию или Swagger |
| 10 | После каждой задачи обновлять `TASKS.md` |

Другие документы проекта: [`backend/CLAUDE.md`](file:///c:/Users/muham/Desktop/instagram-monorepo/backend/CLAUDE.md) — порядок чтения и команды.
